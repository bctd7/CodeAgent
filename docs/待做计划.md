## 3. 三层职责：触发权属于 Runtime

| 层 | 职责 |
| --- | --- |
| Runtime | 何时检查、是否触发、手动或自动、选择模型和预算、读取数据、保存并应用结果 |
| Session | 原始会话历史、分支路径、压缩记录的持久化和查询 |
| memory/compact | 根据传入的有序消息计算压缩范围、调用模型生成摘要、检查输出 |

必须区分“何时执行压缩”和“执行时从哪里切开”。compact 计算切点，不监听会话，不建立后台任务，不自动触发，不读写数据库。

Runtime 后续可按 `contextTokens > contextWindow - reserveTokens` 判断自动触发。compact 的执行入口不得因为上下文未达到此阈值就直接跳过，否则手动压缩无法生效。没有可总结的旧前缀时返回明确的无需处理结果，与自动阈值无关。

## 5. 包结构与输入输出

建议少量按职责划分的文件：

```text
internal/memory/compact/
    types.go       Source、Settings、Input、Plan、Options、Result、错误
    plan.go        输入校验、切点、历史/轮次前缀划分
    estimate.go    与 Pi 对齐的消息大小近似估算
    summarize.go   模型调用、分支处理、拼接、输出校验和用量
    prompt.go      文本序列化及摘要提示词
```

文件可以按实际体量合并，不建立 config/service/store/repository 等额外子包，不建立仅为一次调用服务的通用框架。

逻辑上提供两个独立步骤：

- `Prepare(input Input) (Plan, error)`：纯计算，不调用模型。计划表明是否存在可总结前缀、保留起点及待总结的两个区段。
- `Summarize(ctx context.Context, plan Plan, options Options) (Result, error)`：显式调用注入的模型回调，返回完整摘要和用量。

可依此调整 Go 签名，但不要同时建立多组同义入口。包依赖限于标准库和 llm，不导入 memory 父包、session、runtime、agent、provider 或 tools。

输入与边界约定：

1. Source 至少包含稳定 ID 和 llm.Message；ID 非空且唯一，不按字符串或时间重新排序。
2. Sources 是当前有效历史投影中、尚以原文保留的有序消息。首次为可用历史；后续为上次保留尾部加新增消息。
3. PreviousSummary 单独传入，不能同时作为普通 Source 重复加入；调用方不能把已被旧摘要覆盖的全部原文再次传入。
4. Plan 至少表达 PreviousSummary、历史待总结段、当前轮待总结前缀、是否切分轮次、FirstKeptEntryID（及必要索引）、设置。
5. Result 至少包含 Summary、FirstKeptEntryID、Usage。TokensBefore 等诊断信息如保留，明确是否仅是消息估算，不冒充完整请求精确用量。
6. 保留消息始终是 `Sources[firstKeptIndex:]` 的连续尾部。不保留 KeptSourceIDs 非连续列表，不单独抽出最新用户原文。
7. 若保留 CoveredThroughID，它只能指本次 Sources 中待总结前缀的最后一条；累计摘要还覆盖 PreviousSummary 所代表的更早历史，不能把本次区间冒充累计覆盖范围。
8. 空输入、只有一条消息、没有可总结前缀必须正常处理，不能索引越界，也不调用模型。

## 6. 切点策略：对齐 Pi，不能保留旧算法换名字

先读取参考版本的 `findCutPoint`、`findProjectedCutPoint` 和轮次起点查找逻辑。

本项目只有 User、Assistant、ToolResult 三类消息；不为迁移新增 Pi 专属消息类型。输入已是模型可见投影，因此不在本包实现 Session 元数据投影。

1. 逐条估算消息大小，从最新消息向前累计到 KeepRecentTokens。
2. 按固定版本源码选择累计位置处或其后的最近合法切点；若没有后续合法切点，使用最后一个合法切点。特别验证尾部工具结果自身超预算的情况，仍应保留其对应 assistant，不能退回全部历史。
3. User 和安全的 Assistant 边界可作为保留起点，ToolResult 不可作为起点。不能把旧实现“只向前回退、至少保留指定 token”的规则当作 Pi 规则。KeepRecentTokens 是近似目标，不是精确承诺。
4. 输入必须保持工具调用/结果配对。检查 ID/名称及尚未结束的调用组，不能在跨越切点的工具组中间切开。不要仅凭消息 role 判定复杂的乱序/插入消息输入安全；异常输入应明确拒绝，不生成或伪造工具结果。
5. 切点是 User：普通历史压缩，待总结段为起点到切点之前。
6. 切点是 Assistant 且能向前找到该轮 User：标记 split turn。更早历史截至该 User 之前；轮次前缀从该 User 到切点之前；尾部从切点开始。
7. 找不到该轮 User 时，不虚构用户请求。按 Pi 的无轮次起点分支处理，同时维持工具配对检查。
8. 不抽出用户消息重新插入尾部，不重排消息，不删除原始输入，不隐式补齐缺失的工具结果。

估算与设置：

- 默认设置与 Pi 核心默认值对齐：ReserveTokens=16384，KeepRecentTokens=20000。提供明确默认设置构造，不把所有显式零值悄悄换成默认值。
- KeepRecentTokens=0 按参考切点算法处理；负数拒绝。摘要输出上限计算后必须为正，否则在模型调用前报参数错误。
- 迁移参考源码针对本项目支持消息类型的估算办法。字符数除以 4 是近似启发式，图片有估算占位成本；不得将其描述为精确 tokenizer 或对所有语言都保守。
- Go 字符计数与 JavaScript UTF-16 length 有差异。若选择 rune 计数，明确说明这一适配差异并覆盖中文和非 BMP 字符；不要直接拿 UTF-8 字节数冒充 Pi 字符计数。
- 摘要模型输入预算与主对话预算是不同概念。最终完整请求的系统提示、工具定义及实际消息包装，应由后续调用层重新检查；不恢复旧五阶段预算规划器。

## 7. 摘要策略：普通一次，split turn 最多两次

### 7.1 普通历史压缩

将 PreviousSummary 和待总结历史交给模型，生成一份更新后的摘要。上次摘要为空时使用初始摘要提示词；非空时使用更新提示词。覆盖目标、约束、进度、决定、下一步和关键上下文。

不得将旧摘要原封不动地无限追加，也不得把消息当成新任务继续执行。

### 7.2 切分当前长轮次

严格分开两类输入：

- 历史摘要：PreviousSummary + 当前轮 User 之前的新历史。
- 轮次前缀摘要：当前轮 User 至保留起点之前的消息，重点保留原始请求、已做工作、后续继续所需背景。

有新历史时生成更新历史摘要；没有新历史时直接使用 PreviousSummary，没有 PreviousSummary 时使用稳定的“无更早历史”说明。随后生成轮次前缀摘要。

两部分以固定分隔符和轮次说明直接拼接，不再调用第三次模型合并。第二部分失败时整个结果失败，不返回可安装的半份摘要。失败时允许报告已经消耗的用量，但 Summary 与成功边界不能被误认为有效结果。

输出预算参照固定 Pi 版本：历史摘要使用 `floor(0.8 * ReserveTokens)`，轮次前缀使用 `floor(0.5 * ReserveTokens)`，分别受已知的 Model.MaxTokens 限制。明确 Options 中输出上限的来源，避免用户选项和派生值互相静默覆盖。

### 7.3 序列化、模型调用和失败处理

- 按角色转成带标签的转录文本，由摘要系统提示词限定任务；不将原历史直接作为待继续执行的工具对话。
- 参考 Pi 对工具结果文本的 2000 字符截断及明确截断标记；只影响总结输入，不修改 Session 原文或保留尾部。Go 字符单位需说明。
- 使用当前 Content 中的可见文本、工具名、参数等；保留工具执行失败的事实。不发送 Details、鉴权信息等与总结无关的内部元数据；不解读不透明的 redacted 数据。
- Pi 的文本序列化不是视觉总结。对本项目图片块必须明确处理规则：可使用“此处有图片，未做视觉总结”的占位提示，不发送 base64 冒充文本，不虚构图片内容。这是项目适配差异，要测试并在结果说明中披露。
- 本阶段不实现 Pi 专用工具名的文件读写追踪，不额外造工具适配注册表。文本中的关键路径仍由摘要提示词要求保留。
- 注入 StreamFunc，不导入 provider、不选择默认模型、不读取 API Key 环境变量、不执行工具。
- 检查返回 error、消息终态、StopReason 和有效文本。取消、模型错误、length 截断、意外工具调用、空摘要都明确失败。不能把本地字符串截断伪装成模型成功完成。
- 用现有 llm 流生命周期；处理 nil reader、建流失败、Result 阻塞及 ctx 取消时的 Close。避免 goroutine/reader 泄漏，保留 context.Canceled/DeadlineExceeded 的可判断性。
- 本阶段不自动重试、不重放工具、不返回部分成功摘要。
- 摘要输入超模型窗口时明确失败；不要重新加回四块总结、递归总结、丢弃整条大消息等后备路径。
- 若执行压缩收益检查，只能使用清楚标注的估算；不要把“未超过自动触发阈值”当成手动压缩失败理由。最终请求能否容纳由后续应用层按实际组装结果判断。

## 10. 后续阶段：Session 存储与 Runtime 接入（本阶段不执行）

Session 后续新增压缩记录存储能力。可能需要记录 ID、SessionID、来源历史 head、累计覆盖范围、FirstKeptEntryID、Summary、上一压缩记录关联及创建时间；准确 schema 与迁移在该阶段确定。

约束：

- 压缩记录适用范围须位于当前路径。历史 head/分支变化时，Runtime 不得安装过期候选。
