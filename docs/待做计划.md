# Runtime 重写待做计划

更新时间：2026-10-10。

**状态：Runtime 设计与实施约束文档；Agent 历史整理接口已按本轮单独授权补齐，Runtime 源码尚未开始。** 本文替换原有已完成的 longterm／Hooks 迁移计划，不重复执行那些迁移。第 19 节记录已实现接口及后续接法；开始 Runtime 源码实施仍需用户明确指令。

本计划的目标是让 Runtime 调用现有独立包、确定交接顺序和管理宿主资源。不是重新设计 AgentLoop、Session、Hooks、Permission、MCP 或长期记忆业务。

4. 当前工作树状态。仓库已有大量未提交修改及删除，不能把它们当成可以覆盖或恢复的旧代码。

约束优先级：用户最新决定 → 本文已确认决定 → 当前独立包实际接口 → 示例及旧文档。发现本文与源码不一致时，给出具体接口和无法完成的交接，不自行改其他包，也不声称“都已经具备”。

不追求让旧调用者继续编译，不设计新旧两套流程，不保留旧 Runtime 的兼容入口。文档中的“拟提供”是新 Runtime 的设计，不代表代码已经存在。

## 2. 修改范围与禁止事项

### 2.1 后续源码实施允许范围

- internal/runtime/**。
- Runtime 自身中文说明及本文的实施状态、验收记录。
- 仓库外临时副本中的测试与测试数据。

后续 Runtime 实施不授权继续修改 Agent、Session、longterm、compact、Hooks、Permission、LLM、Provider、MCP、基础工具、统一配置或 CLI。本次单独授权的 Agent 调整仅限 internal/agent/history.go，现已完成，见第 19、24 节。此前独立包建设及本次接口补充均不自动延伸为继续修改其他包的权限。

如果外部接口确有不足：记录“需要什么数据或操作、哪个已有入口缺失、不能完成哪一步、为什么已有入口无法替代”；向用户讨论。禁止先修改再解释。

### 2.2 明确不做

- 不恢复已经删除的旧 Runtime 实现。
- 不执行 git reset、checkout 覆盖、提交或推送。
- 不运行或升级用户现有数据库，不清理用户记忆目录。
- 不在 Runtime 写 SQL、建表、数据库迁移、记忆文件提交或恢复逻辑。
- 不增加 memory_jobs、审批表、任务队列、租约、通用事件表、模型请求快照表。
- 不复制 Agent 的循环、工具调度、历史配对、思考块处理、输入队列和终态判定。
- 不为工具错误、MCP 失败、模型失败、defer 自动重放业务操作。
- 不建立通用插件框架、自动注册机制或多层转发包装。
- 不用正文哈希、时间戳或内容相似性猜测消息身份。
- 不为修复范围外编译错误修改 CLI 或其他包。
- 不因“可能有问题”增加第二遍完整校验；每次校验必须对应明确的信任边界或外部变化。

## 3. 已确认的产品行为

| 事项 | 固定决定 |
| --- | --- |
| 主执行循环 | 由 Agent 负责，Runtime 只消费一个 Driver |
| 普通工具错误 | 回到 Agent 的正常工具反馈，不由 Runtime 重试 |
| Hook Allow | 不能替代 Permission 审批 |
| Hook Defer | 结束本 Run，终态 deferred，无自动重放 |
| Hook 失败 | 明确执行错误或协议错误停止当前 Run；普通日志不是失败，不增加失败处理模式开关 |
| 文件修改互斥 | 沿用已确定的文件锁；取得占用后才能修改，禁止两个 worker 同时修改同一文件 |
| Runtime 默认工具 | 基础四工具之外，默认加入 grep、find、ls；webfetch 由宿主启用 |
| 配置更新 | 模型、策略配置、目录、工具目录等在空闲边界更新 |
| 执行中授权 | 用户真实批准可以在 Run 中更新 Permission.Session，并唤醒相关待审批请求 |
| 原始工具结果 | 先保存原文，再执行 Hook，再独立保存模型可见内容 |
| pending 历史 | 隐藏正文，不回退原文、不补跑 Hook，Agent 对缺失结果生成不可用说明 |
| 压缩时机 | 主模型请求之前，使用已保存的处理后历史；之后执行原生请求 Hook |
| 请求 Hook 改写 | 只影响当前请求，不写回原始历史，不当作持久压缩来源 |
| 辅助模型 | 压缩和记忆整理固定继承触发时主模型，不允许独立指定模型 |
| 辅助工作 Hooks | 压缩和记忆整理不触发用户配置的对话 Hooks |
| 记忆范围 | 项目产生并保存记忆，同一项目的不同会话共享 |
| 记忆检索 | 主模型收到用户消息后，自主调用三个只读工具 |
| 记忆整理 | 正常主 Run 完成并保存后自动后台执行，无手动／自动双模式 |
| 整理失败 | 不推进进度；下次正常主 Run 完成时重试固定来源，无定时器、无重试队列 |
| 关闭时整理 | 取消并等待安全收尾，未成功的不推进 |
| 子任务 | explore 只读；worker 可有文件范围、默认无 shell；禁止孙任务 |
| 主 Run 正常结束 | 等待未完成子任务并交付，必要时让主模型继续，然后才结束 |
| 部分 MCP 失败 | 诊断可见，基础工具和已连接工具可继续；重连／目录刷新在空闲边界应用 |

“跨会话”不等于“跨项目”。本轮不增加跨项目记忆开关、全局记忆工具组或让用户每次选择记忆范围的界面。旧契约对宿主绑定其他目录的能力描述，不构成本轮实现跨项目产品功能的要求。

“无感”表示无需用户为压缩、记忆整理另选模型或逐次发起，不表示失败可以隐藏、消耗可以伪装为零或关闭时可以放任后台继续写入。

## 4. 职责分配

| 组件 | 负责 | Runtime 只做的交接 |
| --- | --- | --- |
| Agent | Run、队列、纠正、模型循环、工具并发、历史投影、取消和终态 | 创建、Submit／Steer、Driver Next／Resolve、取消与关闭 |
| Session | 七表存储、原始与处理后历史、事务、历史路径、摘要关联、子关系、整理进度 | 调用公开方法并保存必要返回 ID |
| Hooks | 命令执行、协议解析、事件聚合、原生模型回调 | 按节点调用，将明确结果翻译成 Driver 决定 |
| Permission | 规则评估、真实批准、一次／会话授权 | 提供可信工具身份和实际路径，展示并回复待审批 |
| tools | 工具领域实现及自身参数处理 | 显式组成目录，绑定执行函数及可信元数据 |
| compact | 估算、合法切点、摘要提示和摘要调用 | 决定触发、准备来源、调用、保存、应用 |
| longterm | 六工具事务、三工具只读、文件校验、提交、恢复、回执 | 绑定项目目录、适配工具、固定批次、调用后推进 Session |
| MCP | 连接、目录版本、刷新、传输、错误 | 生命周期与工具适配，不复制连接状态机 |
| instructions／skills | 指令发现与技能元数据 | 调用已有加载入口并组装提示，不新建发现框架 |
| Provider／LLM | 协议类型、建流、模型结果 | 注入已有 Stream，不修改协议或新增路由规则 |

### 4.1 Runtime 可以持有的状态

- Host 拥有的资源和会话实例引用。
- 本会话 Agent、Session、Permission.Session、Driver 引用。
- 已接受输入附带的 Hook 上下文，消费或丢弃后释放。
- 当前 Run 的 Driver ResponseID 到 Session assistant EntryID 映射。
- 待审批请求、真实 Confirmation 凭据及等待通知。
- 已连接工具的可信绑定和当前固定目录版本。
- 当前已保存的摘要引用、后台整理取消／完成句柄。
- 子任务句柄、文件占用与执行者归属。

这些状态是对外部接口的交接索引，不是第二份持久历史或第二套 Agent 队列。能从 Session 查询的持久事实，不在 Runtime 再维护长期镜像。关停时必须释放短期关联。

### 5.1 防止文件内部再次膨胀

- 每个 Driver 分支只表达该节点顺序；具体跨包调用进入对应文件中的具名函数。
- helper 必须被真实流程调用，不预建通用接口、适配器工厂、策略注册表。
- 不用一个“万能 execution context”装所有业务状态。
- 不要求每层接口都有同名转发方法；调用方可以直接使用独立包的公开类型。
- 错误只在增加实际定位信息时包装，不逐层附加相同前缀。
- 不随意另建 assembly.go、hooks.go、requests.go、events.go、types.go 大杂烩。
- 文件过大先检查是否复制了独立包业务；不能把同一套过度设计拆成更多文件来满足目录表。
- 没有为了凑覆盖率而公开的内部接口或仅供测试使用的生产抽象。

## 6. 对外入口和宿主装配

以下是行为边界，具体 Go 签名在实现前按实际调用者收敛；不复刻旧 Runtime API。

### 6.1 Host

负责创建、打开、列出已打开实例、关闭单会话和关闭 Host。接收已经解析的项目目录、Session Store、模型引用与实际模型配置、Stream、Hook 配置、Permission 策略、MCP 配置及已有包所需选项。

不得在 Host 另写配置文件解析器或凭据解析器。不把“取模型列表第一个”作为默认模型选择规则。模型引用由宿主明确提供并校验存在。

项目目录规范化后固定，不调用进程级 os.Chdir。不同会话的相对路径使用各自绑定目录。

资源是谁创建的，谁关闭；外部注入的共享资源是否由 Host 关闭必须在选项和文档中明确，不重复关闭。

### 6.2 Runtime

单会话提供提交、纠正、取消、审批回复、只读状态、事件订阅、空闲配置更新和关闭。返回 Agent 的 Run 句柄或必要的薄数据组合，不再创建另一套 Run 状态枚举。

事件用于 UI 展示和观察；持久化及 Hook 不依赖 UI 是否订阅。Agent 的 OnEvent 回调必须快速返回，不能在回调中等待 Agent.Close、Run.Wait 或另一个同步事件。

审批是单独的宿主交互数据，不能把用户批准文字塞进普通对话当作已完成授权。

### 6.3 初始化顺序

1. 读取并校验显式配置，固定项目和会话身份。
2. 取得资源占有权；没有所有权不得接管仍活跃的会话。
3. 打开当前版本 Session；旧结构错误原样报告，不升级或清空。
4. 加载当前历史路径、处理后消息及适用摘要。
5. 创建会话权限容器，加载项目指令和技能元数据。
6. 建立基础工具、记忆只读工具及被启用扩展的显式绑定。
7. 连接 MCP；部分失败保留诊断，只应用成功工具。
8. 创建 Agent，注入 UUID RunID 生成器、当前历史和实际模型来源。
9. 领取唯一 Driver，启动唯一节点消费流程。
10. 执行对话 SessionStart；其附加上下文记录真实来源，不伪造一个用户 Run。

初始化任一步失败，只释放已成功取得且属于自己的资源，不能调用业务工具探测“是否可用”。

SessionStart 发生在 Run 之前，其上下文可短暂保留到后续真实 Run；不能为满足 AppendContext 的活跃 Run 条件制造空任务。

### 6.4 恢复

必须先确认本实例拥有会话执行权，再处理未结束 Run。恢复不重新调用旧模型、不重新执行旧工具、不重放 Hook。

GetContext 返回 pending 时保留诊断但不提供原始正文；交给 Agent 的历史省略该不可用结果，由 Agent 自己补配对说明。不能把补充说明伪造成工具确实执行成功的结果。

只有启动记录、没有明确结果的工具保留“执行结果不明”事实。不得猜成 failed、success 或自动重试。

恢复中的 Run 收尾通过 Session 公开接口表达中断事实；不能依赖进程 PID 文本或超时猜测其他执行者已经死亡。

## 7. 正常主流程

    用户提交
      → UserPromptSubmit
      → 接受后交给 Agent.Submit
      → RunStarting：Session.StartRun
      → 已消费输入／纠正入库
      → ModelRequestReady：上下文／压缩／原生请求 Hook／最终预算
      → ModelCallStarting：记录调用尝试
      → Agent 调用模型
      → ModelResponseReady：原始响应入库／响应观察 Hook
      → Agent 决定工具调用或结束候选
      → 工具前 Hook／最终参数校验／Permission／真实审批
      → Agent 执行工具
      → 原始结果入库／工具后 Hook／处理结果入库
      → 批次 Hook／宿主上下文交接
      → Agent 下一轮
      → 正常结束候选：子任务收齐／Stop Hook
      → 必要时 Repeat；否则 RunFinishing
      → Session.FinishRun
      → 对用户完成
      → 后台自动整理本项目长期记忆

步骤是节点的因果顺序，不要求所有工具串行。工具并发由 Agent 负责；Runtime 不把一个等待审批的工具变成阻塞整个 Driver 消费的全局锁。

取消、错误、deferred 走对应收尾，不强行补齐正常成功路径。

## 8. Driver 节点交接表

| 节点 | Runtime 必须完成 | 交回 Agent | 禁止行为 |
| --- | --- | --- | --- |
| RunStarting | 使用节点 RunID 和真实用户消息 StartRun，绑定待交付宿主上下文 | Continue 或 Stop | 先造自己的 RunID／第二条输入队列 |
| InputConsumed | 保存 Agent 实际消费的纠正 | Continue 或 Stop | 将尚在队列中的输入写成已消费 |
| ModelRequestReady | 形成当前上下文、必要压缩、请求 Hook、最终预算 | Continue + 可选 RequestContext；错误 Stop | 修改共享输入、永久覆盖原始历史 |
| ModelCallStarting | RecordStep，记录将发生的 Stream 尝试 | Continue 或 Stop | 在请求准备阶段提前计费或虚增步数 |
| ModelResponseReady | 保存 Assistant 原文和实际 Origin，建立 ResponseID 关联，调用观察 Hook | Continue 或 Stop | Hook 改写 Assistant 原始事实 |
| ToolStarting | 前 Hook、最终参数、schema、可信目标、Permission、必要审批和启动记录 | Continue／Skip／DeferRun／Stop；带最终参数 | Runtime 自己 Execute 工具或凭 Hook Allow 放行 |
| ToolFinished | 原始结果与明确状态事务保存，后 Hook，确认处理结果 | Continue + 可选 ToolContent；错误 Stop | 用替换正文覆盖原文或猜 Executed |
| ToolBatchFinished | PostToolBatch，保存并追加本批宿主反馈，交付已准备的相关上下文 | Continue + ContextMessages 或 Stop | 把上下文插在未完整保存的 assistant／tool 组中 |
| RunEnding | 正常结束候选下收齐子任务；Stop Hook 决定是否继续 | Continue／Repeat + ContextMessages／Stop | 强制把取消、length、error 重新变成成功任务 |
| RunFinishing | FinishRun，记录 Agent 最终状态和用量，清理当前 Run 关联 | Continue 或报告持久故障 | 提前宣告成功，再异步补写 FinishRun |

### 8.1 Driver 并发边界

- 只能一个 Next 调用者。
- 不要求所有已经交付的 ToolStarting 同时立即 Resolve。待审批可挂起，让其他节点继续收尾。
- 待审批有准确节点身份，最终只 Resolve 一次；重复 UI 回复明确无效。
- 等待取消必须解除审批等待，但不能直接遗弃已经交付的事实收尾节点。
- 不持有 Runtime 全局锁执行 Hook、等待审批、等待子任务、调用模型或关闭资源。
- Resolve 的等待 context 与 Run 的取消 context 区分。Run 已取消不意味着可以跳过必须完成的事实交接。
- Agent 可能在启动交接前后收到取消／纠正；最终是否执行以 ToolOutcome 为准。
- 持久故障调用 Agent.StopExecution 关闭准入，再完成已有工作的收尾；普通领域错误只结束当前 Run 或作为工具结果返回。

## 9. Hook 规则与上下文

### 9.1 对话 Hook

- SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、PostToolUseFailure、PostToolBatch、Stop、SessionEnd 使用现有 Hooks 入口。
- 原生 BeforeModelRequest／AfterModelResponse 分别接到请求准备和响应保存节点。
- 不为 Hooks 新造另一个 Driver，不把脚本执行移入 Runtime。
- CommonInput 只填实际具备的字段。没有真实 transcript 文件就不填 TranscriptPath，数据库文件不是 transcript。
- PreToolUse 的 AdditionalContext 等宿主反馈按来源保存，在合法上下文节点交付，不混成工具结果。
- SystemMessages／Reports 是诊断和展示信息，不默认全部灌入模型。
- 明确业务 deny、ask、defer 与 Hook 执行／协议错误分开处理。

### 9.2 模型可见结果

1. AppendToolResult：原始结果、最终参数、明确执行状态及关联一起保存，Processing=pending。
2. 执行成功或失败工具 Hook。
3. CompleteToolProcessing：nil 表示原样，非 nil 表示替换，空切片表示明确清空。
4. Resolve 将同一份可见替换交给 Agent。

Hook 失败时不得把 pending 当成 original。原文保留审计，下一次恢复按已确认的隐藏策略处理。

工具结果身份、ToolCallID、工具名、IsError 和执行状态不由 UpdatedToolOutput 重写。可替换的是模型可见正文。

### 9.3 请求 Hook

固定顺序：有明确来源的历史与摘要应用 → BeforeModelRequest → 最终请求预算检查 → ModelCallStarting。

请求 Hook 的临时新消息、删除或改写只存在于本次 RequestContext，不覆盖 Session 原始记录，不凭正文或顺序给它伪造 EntryID。最终超限不再反过来递归压缩 Hook 的临时输出，也不反复重跑 Hook。

### 9.4 内部自动工作

压缩不触发对话 Hooks。后台记忆整理 Agent 不触发这些 Hooks，只安装 longterm 本次 Task 的六工具和执行预算。

这项决定不能解释为后台取得任意 shell、基础文件工具、MCP 或子任务权限。

## 10. 工具目录与最终参数

### 10.1 显式集合

- 基础默认集合仍由 internal/tools.New 构造：read、当前平台命令工具、edit、write。
- Windows 命令工具为 powershell，其他平台为 bash。
- Runtime 在基础四工具之外，默认通过各自构造器加入 grep、find、ls，不改成自动注册。internal/tools.New 本身仍只返回原有四工具。
- 前台长期记忆使用 Service.ReadTools 与 CallReadTool，只含 memory_list、memory_read、memory_search。
- MCP、subagent、webfetch 是扩展接入；webfetch 只有宿主启用时才加入。基础集合不因 Runtime 工作而改写。
- read 的图片辅助能力尚未接入，不借 Runtime 工作改变读图行为。

注册时校验工具名称不冲突，工具定义与执行函数一一对应。模型可见名称不能决定“这是 MCP／只读／可信”。

### 10.2 一次最终参数处理

顺序固定：

1. 根据实际工具绑定找到原调用。
2. 执行 PreToolUse。
3. 应用 UpdatedInput，得到唯一的最终参数。
4. 对最终参数执行一次通用 schema 校验。
5. 提取可信能力、实际文件目标和必要的目录信息。
6. Permission 评估。
7. 等待真实批准时保持这份参数和请求身份固定。
8. 放行时保存启动事实，Resolve 交给 Agent 执行。

独立工具自己的领域参数校验仍保留；Runtime 不试执行工具来验证参数。审批后未发生变化的参数不重新执行 Hook，不做第二轮完整 schema 校验。

最终参数同时用于权限判断、启动记录、未执行记录和实际执行，不能分别使用改写前后两版。

文件路径处理只承担权限和共享文件占用需要的实际身份解析；不能只做字符串前缀判断。新文件按已有父目录解析，不为验证创建目标文件。不能声称这完全消除了外部进程造成的文件系统竞态。

## 11. 审批和执行中授权

### 11.1 普通审批

固定协议：

    Permission.Session.Evaluate
      → Allow：继续
      → Deny：Skip，记录拒绝
      → Ask：保存真实 Confirmation 并展示
          → 用户 Once／SessionTool／Reject
          → Grant
          → 再次 Evaluate
          → 按新结果继续或拒绝

Grant 成功不等于执行许可；必须重新 Evaluate。Deny 优先于普通会话授权。

Confirmation 含内存凭据，不能通过 JSON 重建。UI 只持有审批 ID 和展示快照，实际凭据由所属会话保存。

### 11.2 会话授权更新

用户选择 SessionTool 后，唤醒同会话中相同可信工具身份的普通审批，重新评估。不是把所有待审批一键改成 Allow。

授权绑定来源与工具，不扩展成整台 MCP 服务器、所有文件或所有会话。Once 只用于该请求快照。会话关闭清空授权；不写审批表。

策略配置更新与用户批准不同：策略、工作目录等配置在空闲边界变化；真实批准可在运行中变化。

### 11.3 Hook 强制 Ask

Hook Ask 即使遇到普通权限 Allow，也要求当前调用获得真实同意。不能被过去的 SessionTool 授权绕过。

普通 Permission 没有生成 Confirmation 时，不伪造一个用于 Grant 的凭据。Hook 本次确认在宿主等待状态中表达，只批准当前调用；若同一调用同时存在普通审批，则分别满足两项条件。

Hook Allow 只消除 Hook 自身阻拦，不覆盖普通 Deny／Ask。

### 11.4 等待失效

取消、会话关闭、节点已结束或明确撤销使相关 UI 回复失效。不得因迟到的批准重新启动已经取消的工具。

有启动记录也不证明工具产生副作用。实际状态必须用 Agent.ToolOutcome 更新；Executed=false 与已有启动交接记录可以同时存在。

## 12. Session 接线

以现有七表及公开接口为准，不新增表。

| 数据 | 入口及要求 |
| --- | --- |
| 用户输入与 Run | StartRun，一次事务 |
| 已消费纠正／Assistant | AppendMessage；Assistant 保存实际 Origin |
| 调用尝试 | RecordStep |
| 工具启动 | RecordToolStart，使用最终参数 |
| 工具结果 | AppendToolResult，传明确 Status／Executed／ErrorMessage |
| 处理结果 | CompleteToolProcessing，区分 pending／original／replaced |
| 宿主反馈 | AppendContext，明确 SourceKind／SourceID |
| 原始历史 | GetCurrentHistory |
| 处理后上下文 | GetContext，pending 的 Message 为 nil |
| 摘要 | SaveCompaction／LatestCompaction |
| 子任务 | CreateChildTask／GetChildTask／ListChildTasks／DeliverChildResult |
| 整理批次与进度 | NextMemoryBatch／GetMemoryProgress／AdvanceMemoryProgress |
| 终态 | FinishRun，包含合法 deferred |

Driver.ResponseID 只用作当前执行节点到保存后的 Assistant Entry 的直接关联，不当作数据库 ID。工具关联由所属 Assistant Entry 和调用 ID共同确定，不假定工具调用 ID 在全部历史中全局唯一。

宿主上下文虽使用 LLM user 消息形状，持久记录必须 Kind=context 并带来源。子任务交付使用专用入口，不通过普通 AppendContext 伪造 child_run 来源。

未执行工具没有真实开始就不伪造 StartedAt。只有启动而没有结果的记录保留 Executed 未知，不猜测。

## 13. 自动压缩

### 13.1 已固定的行为

- 对用户无感，不暴露独立摘要模型选项。
- 继承触发这次压缩的主模型及传输／请求配置，执行期间固定。
- 当前模型窗口未知时不猜数值，不执行自动压缩，提供诊断。
- 请求还能容纳时，压缩失败可继续原请求；已知超限则结束本 Run，不能发送已知装不下的请求。
- 不自动拆分、递归压缩、切换更大模型或反复尝试摘要。
- compact 自己的合法切点和最多两段摘要调用不是 Runtime 自动重试，不重写该算法。
- 压缩消耗与主对话调用统计区分记录，不伪装成零消耗。

### 13.2 来源和保存

压缩来源从 Session.GetContext 的当前祖先路径取得，排除 pending 正文后保留同序的记录与消息数组，调用 Agent.ProjectHistory 完成模型适配。真实消息通过 SourceIndex 直接关联 EntryID；生成说明只有本次 compact 输入中的临时唯一 ID，不冒充 Entry。不从原始工具结果回退，不压缩请求 Hook 的临时改写。

使用适用于当前路径的 PreviousSummary，已经覆盖的原文不再次放入 Sources。调用顺序是 Prepare → Summarize → SaveCompaction → 应用。失败或取消不安装未保存摘要。

SaveCompaction 传实际 HeadID、PreviousID、按祖先路径排列的真实 SourceIDs、换算后的 FirstKeptIndex、Summary、Origin、Usage。compact 的输入可能重排工具结果并包含生成说明，因此不能原样复制其下标；换算规则见第 19 节。不能只保存一个全局最大 Sequence 作为覆盖边界。

遇到 pending 不回退正文，复用 Agent.ProjectHistory 对缺失结果的既有补齐规则；结构错误的旧响应也由该入口按原规则过滤。compact 继续校验输入和合法切点。Runtime 不复制这些算法，具体交接见第 19 节。

### 13.3 预算

复用 compact.EstimateTokens 和现有 Settings；完整请求还必须计入系统提示、工具定义及预留输出。估算是启发式，不声称是精确 tokenizer 或计费。

不重估同一份未变化的大对象多次。压缩前判断是否触发，压缩／请求 Hook 改变上下文后再检查最终请求，这两次目的不同，不能省略最后一次，也不循环检查到“满意”为止。

阈值使用模型窗口减去有效输出预留；不另造一个与模型上限冲突的固定窗口。具体零值及过小窗口处理在实现时沿用包的合法性约束，错误明确返回，不偷偷缩减历史。

### 13.4 应用边界

RequestContext 只替换本次请求，不永久修改 Agent.history。因此每次请求都必须正确应用当前已保存摘要及保留尾部，不能只处理压缩发生的那一轮。

**所需 Agent 接口已补齐，接法见第 19 节。** 临时测试已验证来源对应、压缩切点换算和保留历史重新整理；Runtime 的真实 Driver／Session 接线仍待实施，不能把接口验收描述为 Runtime 已完成。

## 14. 项目长期记忆

### 14.1 前台

一个项目绑定稳定的记忆目录及 ScopeKey，同一项目的多个会话共享这个 Service 所代表的已提交内容。工具参数不允许模型自行更换目录。

主模型先看到用户消息，然后自行决定使用 memory_list、memory_search、memory_read。系统提示只说明用途、适用范围和内容可信边界，不预载全部记忆，不先运行检索模型。

前台三个工具与后台对应工具复用原 schema、解析和结果编码。前台拒绝写工具；不共享后台暂存、读证据或批次失败状态。

### 14.2 触发与固定模型

只有正常主 Run 的 success + stop 已经通过 FinishRun 保存后，才启动或唤醒本会话的后台整理。

触发时固定该主 Run 的实际主模型和请求配置。不允许 MemoryModel、SummaryModel 或其他独立模型覆盖项。后续 UI 切换模型不改变正在执行的内部任务。

后台工作不阻塞用户收到主 Run 结束结果，也不占用该主 Run 的输入队列。Runtime 只保存正在工作的句柄和唤醒信息；待整理来源由 Session 查询，不维护第二份任务列表。

### 14.3 单个批次

1. NextMemoryBatch(scope)：取得当前有效路径上最早未整理的正常主 Run。
2. 使用该批次给出的固定 ID、来源 Entry ID 及原始消息构造 longterm.Batch。
3. 调用 Consolidate。
4. 只有 error=nil 且正常成功／Duplicate，才 AdvanceMemoryProgress。
5. 继续查询后续固定批次；没有批次则结束。
6. 任一失败停止本次整理流程，保留进度，下次正常主 Run 完成时再尝试。

不偷偷截断超限来源，不把一个批次拆成新 ID，不因主对话新增消息修改已经取得的批次内容。

记忆已提交而进度保存失败：下次相同固定批次命中 longterm 成功回执，然后补推进。不自行复制成功回执或写 memory_jobs。

分支切换由 Session 的祖先路径和条件推进校验处理。不得用另一分支较大 Sequence 跳过来源，也不维护 Runtime 自己的分支游标。

### 14.4 Execute 适配

使用独立 Agent 执行 longterm.Task，复用 AgentLoop。其 Driver 只落实本任务预算与结果交接：

- 工具只来自本次六工具 Task，按原始顺序串行执行。
- 不安装对话 Hooks、基础文件工具、shell、MCP、子代理或前台对话能力。
- 模型调用前检查 Turns。
- 新工具批次启动前检查剩余 ToolCalls。
- 每轮完整请求检查 InputBytes。
- 流式模型内容和工具结果检查累计 OutputBytes，超限取消，不等全部结果返回后才发现。
- 任一中间工具失败、取消、预算超限或收尾失败使 Execute 返回错误。
- Execute 返回之前关闭全部模型流并等待 Agent 收尾。
- 只有完整正常 stop 才可使 longterm 进入提交；不能将空 ExecutionResult 当成功。

不把后台 Agent 注册成普通子任务，不对它建立 child_tasks 关系，不伪装成用户主动发起的 Run。

### 14.5 并发、恢复和关闭

longterm/storage 已负责同目录整理锁、短期数据锁、提交恢复和回执。Runtime 不再套一把持续覆盖后台模型调用的前台读取锁。

前台读取可在后台模型整理期间看到上次完整提交；不要求每次独立读取共享一个跨调用快照。

关闭时取消后台并等待安全收尾，随后才 Close Service。发布提交后的恢复和错误含义以 longterm 为准，不能宣称取消一定回滚了磁盘。

## 15. 子任务

### 15.1 现有协议

实现现有 subagent.Controller：Spawn、Send、Wait、Cancel。使用现有工具名称及 schema，不复制工具解析，不新增自动注册。

Controller 绑定父会话作用域，传入任意子任务 ID 不能绕过归属校验。

子任务用普通 Session、Run、消息和 Agent。child_tasks 只保存关系、角色、文件范围和关联，不复制运行状态。

### 15.2 角色

- explore：只读工具集合，不安装修改、shell 或创建子任务能力。
- worker：可修改，文件范围可选，默认无 shell。
- 子任务不获得父会话待审批票据或未经批准的额外能力。
- 子任务不能创建孙任务，工具目录与 Controller 校验同时约束。
- 现有 SpawnRequest 中可选 model_ref 的含义不受“压缩／整理不准独立模型”决定自动扩大影响；如用户另行调整子任务模型产品规则，单独讨论。

### 15.3 正常完成与交付

父 Run 准备正常结束时，等待当前子任务结束和清理。完成结果绑定具体 child Run，通过 DeliverChildResult 原子写入来源与父上下文。

同一个父 Run 对同一个 child Run 的相同交付去重。结果不同不能覆盖旧交付；不是“每次 Wait 都再追加一次”。

有新的相关结果时，在 RunEnding 使用 Repeat 与已保存的 ContextMessages，让主模型有机会整合结果，再次判断是否结束。不能先 FinishRun，再尝试向已结束父 Run 写交付。

Wait 超时只结束等待，不取消底层子任务。父 Run 取消／关闭则取消其活动子任务并等待清理，不继续等待正常成功。

### 15.4 共享工作区

文件占用通过可信规范化路径关联执行者。明确文件范围的 worker 在其 Run 生命周期内持有范围；未声明范围的 worker 在首次修改时取得相应占用并保持到该 Run 收尾。

沿用已确定的文件锁互斥方案：任何修改必须先取得对应路径的占用，未取得就不能执行修改。同一文件不能同时分配给两个修改者，不再将“是否允许两个 worker 同时修改”列为产品待决项。锁等待响应取消，Run 收尾释放占用；不增加另一套冲突调度或自动重试机制。

不会自动撤销已产生的文件变化。子任务失败、取消不等于工作树恢复原状。

读后改检查和文件占用不是替代 Permission。无法可靠枚举目标的工具不能被伪装成只修改已锁定的几个文件；默认不给 worker shell 正是已确认工具边界之一。

## 16. MCP 与工具目录更新

MCP Manager 负责连接事实、目录版本和 stale 错误。Runtime 只绑定工具定义和调用路由，保留服务器身份。

启动时部分服务器失败：汇总诊断，保留基础工具及其他成功服务器；不把失败服务器的旧目录当作当前可用目录。

重连和目录刷新在空闲边界应用。正在执行的工具调用保持原绑定，不中途改指其他服务器或新 schema。stale／断线错误作为当前工具失败反馈，不重新执行。

外部工具的 readonly hint 不等于本地可信只读权限。Permission 所需 Source／Capability 由适配绑定提供，不能来自模型参数。

## 17. 结束、取消和错误矩阵

| 情况 | 当前 Run | 后续准入 | 重试与持久化 |
| --- | --- | --- | --- |
| 用户拒绝普通工具 | Agent 获得拒绝结果，可继续推理 | 正常 | 保存未执行结果，不造启动时间 |
| 普通工具领域失败 | 正常工具反馈 | 正常 | 原始结果及处理结果分别保存，不自动重试 |
| Hook deny | 拒绝当前工具 | 正常 | 不当成 Hook 崩溃 |
| Hook defer | deferred 收尾 | 收尾后可接受新任务 | 不创建自动重放 |
| Hook 执行／协议致命错误 | 停止当前 Run | 按资源是否可用决定 | pending 原文不泄露 |
| 用户取消／关闭 | Agent 合作取消，清理子任务和待审批 | 关闭则拒绝 | 不等待正常 Stop Hook 将其改回成功 |
| 模型截断或 Provider 错误 | 沿用 Agent 终态 | 无持久故障则允许后续任务 | 不自动换模型或重播 |
| Session 写入失败 | 停止并关闭执行准入 | 当前实例不可继续执行 | 收尾、报告，禁止先继续执行再补写 |
| 压缩失败 | 原请求可容纳则继续，否则结束 | 正常 | 不安装失败摘要，不自动循环压缩 |
| 后台记忆失败 | 已完成主 Run 不被改成失败 | 前台正常 | 不推进，下次正常主 Run 完成再尝试 |
| MCP 调用失败 | 当前工具错误 | 其他可用工具继续 | 不重放具有副作用的调用 |

Hook 失败固定采用停止当前 Run 的处理，不增加“停止／跳过”双模式。Hooks 明确报告的执行错误、协议错误或顶层 error 均按失败处理；普通 stderr、状态提示和无错误的诊断只展示。明确 deny、ask、defer 沿用各自控制语义，不误判成 Hook 故障。SessionEnd 发生在关闭收尾阶段，失败只汇总报告并继续释放资源，不能重新打开或改写已结束 Run。

关闭顺序：拒绝新准入 → 请求取消活动主／子任务及后台整理 → 解除待审批 → 持续完成 Driver 收尾 → 等待 Agent／后台结束 → SessionEnd → 清空授权与占用 → 释放拥有的 Manager／Store／Service／OS 锁。资源关闭错误汇总报告，不因一个错误跳过后续释放。

## 18. 空闲修改边界

修改模型、工作目录、策略配置、Hook 配置、工具目录或历史分支之前，确认没有活动 Run、排队输入、待审批和仍影响本会话的子执行。

优先使用 Agent.WithExecutionBoundary，不能仅先读 Snapshot 再修改，留下检查与修改之间的竞态。

取消请求不是“已经空闲”；必须等清理完成。后台整理使用固定来源和模型快照；涉及其项目绑定或资源销毁的修改必须先取消并等待它结束。

运行中的用户批准不走这个配置修改流程。它只更新明确请求对应的 Permission.Session 选择。

## 19. 已补齐的 Agent 历史整理接口及压缩接法

### 19.1 实际接口

本次仅修改 internal/agent/history.go：

    type ProjectedMessage struct {
        Message     llm.Message
        SourceIndex int
        Generated   bool
    }

    func ProjectHistory(
        history []llm.Message,
        targetModel llm.Model,
        originMap map[*llm.AssistantMessage]ModelOrigin,
    ) ([]ProjectedMessage, error)

SourceIndex 是本次输入 history 的零基下标，不是输出下标，不是 Session.Sequence 或 EntryID。Generated=false 时指向真实输入消息；Generated=true 时代表自动补出的缺失工具结果说明，其 SourceIndex 指向所属 Assistant，而非一条不存在的工具结果记录。

输入、输出及共享嵌套数据按只读使用。originMap 必须以本次输入中的实际 Assistant 对象为键；不能把另一轮查询得到的消息对象作为键。

prepareRequestHistory 保持原签名，只复用 ProjectHistory 并组装完整 llm.Request。pairToolResults 保留原配对与排序规则，同时携带来源位置；projectAssistantThinking 规则不变。Driver、loop.go、队列、调度及取消协议没有修改。

### 19.2 Runtime 准备来源

1. 读取 Session.GetContext 当前路径及适用摘要。
2. 根据已保存摘要的真实覆盖边界排除已覆盖前缀。
3. 排除 pending 正文，同时建立一一对应的 inputRecords 和 history；两者长度、顺序一致。不能先生成下标表，再单独过滤 history。
4. 从这些 inputRecords 的 Origin 为实际 Assistant 对象建立 originMap。
5. 调用 ProjectHistory(history, 当前主模型, originMap)。
6. 对每项 Generated=false，用 inputRecords[item.SourceIndex].EntryID 关联真实来源；无需比较正文或指针身份。
7. 对 Generated=true，仅为这次 compact 输入分配不会与真实 EntryID 冲突的临时唯一 ID，并保留“生成说明→所属 Assistant”的关联。该 ID 不写 Session、不新增消息记录、不形成另一套持久编号。

Agent 已经处理过滤、工具结果排序、缺失结果补齐和思考块规则；Runtime 只处理上面的身份关联与跨包参数转换。

### 19.3 压缩边界换算

compact.Prepare／Summarize 的 FirstKeptIndex 对应投影后的 compact Sources。Session.SaveCompaction 的 FirstKeptIndex 对应将要保存的真实 SourceIDs。这两份列表在存在重排或生成说明时不同，禁止直接复制下标。

换算固定为：

1. 按 compact 返回的切点，将本次投影项分为覆盖前缀与保留尾部。
2. 两部分都通过 SourceIndex 关联真实记录；Generated 项不加入真实 SourceIDs。生成说明属于所在完整工具组，不能独立成为持久边界。
3. 将实际参与的真实 EntryID 按 inputRecords 的祖先路径顺序排列，形成 Session 的 SourceIDs；记录的是来源引用，模型请求仍保持 Agent 整理后的工具顺序。
4. Session 的 FirstKeptIndex 等于这份真实来源列表中被覆盖的前缀数量。合法 compact 切点不会把同一工具组拆开，因此工具组内部重排不会把同一真实来源分到边界两侧。
5. 保存 HeadID、PreviousID、上述 SourceIDs 与换算后的 FirstKeptIndex，以及摘要、模型来源和用量。

例如投影来源位置为 [0, 2, 4, 3, 2(生成), 5]，compact 保留从投影位置 5 开始。真实来源按历史路径保存为 [0, 2, 3, 4, 5]，Session 的 FirstKeptIndex 为 4，不能填 5，也不能重复保存生成说明所属的 2。

任何来源转换异常都明确返回错误，不以序号相近、正文相同等方式修正身份。

### 19.4 应用及后续请求

保存摘要后，以真实覆盖末 Entry 为边界保留后续处理后历史。调用同一个 ProjectHistory 对尾部做模型适配，保持 Origin 对应；把摘要和整理后的尾部组成 RequestContext，再执行原生请求 Hook，最后交给既有 Driver。

RequestContext 只影响本次请求。因此后续每次 ModelRequestReady 都应用已保存摘要和当前有效尾部；恢复会话或模型改变时，仍对选定尾部调用同一入口。不得因某一轮压缩成功就假定 Agent 内部历史已经被永久替换。

摘要作为宿主上下文参与请求，不改写原始消息。该方式只需要既有 Driver 的 Decision.RequestContext，不增加 Driver 节点、History setter 或新的执行循环。

### 19.5 当前完成程度

接口代码和临时边界验证已完成；原先“不能复用 Agent 整理并关联来源”的接口缺口已补齐。已验证生成说明不会被当成真实来源、工具重排后来源仍准确，以及 compact 切点到真实覆盖边界的换算。

| 组 | 必要验证 |
| --- | --- |
