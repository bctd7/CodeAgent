# Agent 审计待修改项

本文件记录人工审计中确认的修改与保留决策。以下各项均为**待实现、尚未验证**，不代表代码已经修改或完成验收。

以当前 `internal/agent/types.go` 为接口基准，不修改其中的类型、字段、枚举值和 JSON 标签。其他实现适配这些定义，不恢复旧的 `RunStatus` 或已经注释的 `MaxSteps`。本文件中的新决策替代此前关于默认调用上限及立即切换模型的约定。

## 1. 当前不启用模型调用次数上限

**状态：待实现、尚未验证。**

当前类型定义已将 `MaxSteps` 注释，其他实现应移除默认 20 次上限及其残留逻辑。调用次数上限是运行策略，不是模型协议要求。

修改要求：

- 不启用模型调用次数上限，不恢复 `MaxSteps`、默认值、数值校验及上限终态逻辑。
- 不再采用“零表示无限、正数启用上限”的旧方案。
- 保留实际模型调用次数统计；已发起但建流失败或被取消的调用仍计数，单纯选择模型不计数。
- 保持 `MaxParallelTools` 的默认规则不变，不能一起取消并发限制。
- 旧 demo 如仍引用已移除的配置或状态，单独记录兼容问题，不通过改回 types 来迁就。本次不修改 demo。

长任务或 Goal 模式未来可由外层运行管理设置时间、费用或调用预算，本轮不实现预算系统。不限制调用次数不代表已经具备长时间任务所需的上下文管理、持久化或恢复能力。

## 2. 保留输出截断识别及当前停止策略

**状态：待实现、尚未验证；保留截断识别，不增加自动续写。**

一个 Run 内模型调用的次数与单次响应的输出 token 限制是两回事。长任务可以由很多次较短的模型调用组成，但任何一次响应仍可能达到输出上限。

当前决策：

- 保留 LLM 层的 `StopLength`，识别单次模型响应因长度限制而结束。
- 使用当前类型中的 `RunStateSuccess` 与 `RunStopTruncated`（值为 `length`），不再使用旧的截断状态。这里的 success 表示调用成功返回，不表示回答完整；调用方需要同时检查 StopReason。
- 收到截断响应后停止 Run，不自动续写，不执行其中的工具调用。
- 保留已收到的原始响应供观察，不执行其中可能不完整的工具调用，不修补或伪造参数。
- 不因取消默认调用次数上限，而删除截断处理或改成无条件继续循环。
- 自动续写属于后续独立设计：需要区分文本续写与重新取得完整工具调用，明确上下文构造和避免重复执行的规则。

协议依据：Anthropic 官方将达到请求 `max_tokens` 限制的响应标记为 `stop_reason = "max_tokens"`，并说明截断可能造成工具调用不完整。[停止原因与处理说明](https://platform.claude.com/docs/zh-CN/build-with-claude/handling-stop-reasons)

## 3. 模型切换在下一次请求边界生效

**状态：待实现、尚未验证。**

将“选择模型”与“停止执行”分开，避免为模型切换维护请求局部取消和特殊恢复流程。

- `SetModel(model, options)` 成组记录新的模型配置，不取消当前模型请求，不新建 Run，不清空用户输入队列。空闲时直接生效。
- 当前模型响应正常完成；其中符合执行条件的工具按原有规则执行。模型切换本身不再跳过尚未启动的工具。
- 下一次模型请求开始前应用最新选择；连续切换取最后一次目标。请求开始时固定本次 Model 与 Options，生成期间不再修改。
- 当前 Run 已自然结束时，不因待切换模型而额外调用一次模型；配置在进入空闲时生效，供下一次任务使用。
- 保留“切换请求已接受”和“配置已生效”通知，以及 Snapshot 中当前模型和待生效模型的含义。
- 用户取消、纠正、关闭继续具有各自原来的行为；模型切换不代替这些操作，不因切换复活已经取消的任务。
- 保留跨协议历史投影和思考来源检查；每次响应的来源及用量按实际使用的模型记录。

## 4. 简化 Run 内部控制流程

**状态：待实现、尚未验证。**

- 删除 `runPhase` 的残留引用，以及仅为模型切换而存在的 `stepCancel`、`stepMu`、`stepCancelledForSwitch` 和相关分支。模型调用直接使用 Run context，流资源仍在调用结束时关闭。
- 工具调度不再检查待切换模型；只依据取消、纠正、并行规则等原有条件决定是否启动工具。
- 不恢复 `activeRun.cancelling`：利用已有 Agent 取消状态，在同一临界区完成首次取消与旧队列移除；重复处理同一 Run 的取消不得清掉后来提交的新任务。
- 不恢复 `activeRun.finishing`：合并最终输入检查、终态确定、结果保存和执行权交接，避免“决定结束”与“正式提交结果”之间再次接受纠正。外部事件回调放在锁外。
- 不新增控制事件队列、同义阶段枚举或替代布尔值。先通过明确的循环边界和现有锁组织流程。
- 结果构造改用当前 `State / StopReason / RawStopReason / ErrorMessage / Error`。保留 Safety 与截断原因；普通失败、取消不伪造服务端结束原因。
- `Error` 暂时保留，前端错误说明以 `ErrorMessage` 为准；`RawStopReason` 仅保存协议原始原因，不与错误说明混用。不要修改 types 中现有字段及 JSON 标签。
