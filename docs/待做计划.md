# CodeAgent 下一阶段：Agent 核心、工具调度与运行中交互

## 一、目标、职责与实现范围

本阶段在已有 LLM 层之上实现可复用的 Agent 核心，并通过现有控制台验收。本文件是已确认的设计与分阶段执行计划；计划落盘不代表对应代码已经实现。

**目标：** Agent 可以维护执行所需的内存历史，后台处理用户任务，调用模型和工具，接收纠正、排队输入、取消及模型切换。demo 和未来 UI 使用相同接口，不各自实现循环。

明确三个概念：

- **Session：** 一段具有独立身份的会话，可以包含多次 Run，其生命周期不等同于某个 Agent 实例。后续独立的 `session` 包负责会话元数据、历史保存与恢复、分支等会话管理能力。
- **Run：** 一次已接受的用户提交及其后续模型、工具执行；纠正和模型切换不创建新 Run。
- **Step：** 一次模型调用，以及该响应产生的工具调用处理。

本阶段一个 Agent 实例服务于一个会话，持有执行所需的内存历史；不在 Agent 包内实现独立的 Session 管理系统。后续由装配层加载 Session 历史并交给 Agent，Agent 负责执行，Session 层负责组织与保存会话。关闭 Agent 不等于删除会话；本阶段尚未持久化的内存历史不会自动恢复。

排队的用户消息分别创建新的 Run，按提交顺序执行。它们与模型自行维护的 todo 计划无关。

### 本轮实现

- Agent 后台运行、运行句柄及结果等待。
- 当前会话的内存历史维护和请求消息准备。
- 通用工具定义、执行、受限并行及错误回传。
- Agent 事件与现有 LLM 事件转发。
- 用户纠正、后续消息排队、取消。
- 运行中跨模型、跨协议切换。
- 用加法及少量本地演示工具验收。

### 本轮不实现

独立的 `session` 包及会话管理（会话列表、标题、落盘、恢复、分支等）、上下文压缩、长期记忆、自进化、SubAgent、sandbox、权限审批、MCP、正式文件工具、UI、自动重试与自动降级。计划定义它们的接入边界，不创建空实现或通用插件框架。

参考 Pi 系列的循环和工具职责划分、Crush 的后台运行与展示分离。参考项目的 Clone、hooks、完整配置和订阅系统不作为必需功能。

## 二、Agent 的公共接口与数据归属

### 运行入口

Agent 内部使用同步循环，通过事件回调交出进度；Agent 对外管理后台执行，不要求调用方自行组织 goroutine 和队列。

接口职责确定如下，具体 Go 类型保持小而明确：

| 接口 | 职责 |
|---|---|
| `New(config)` | 注入模型配置、模型调用函数、工具和事件接收函数 |
| `Submit(ctx, message)` | 接受用户消息，立即返回运行句柄；空闲时启动，忙碌时排队 |
| `Steer(message)` | 向当前活动 Run 提交纠正；没有活动 Run 或正在取消时返回明确错误 |
| `SetModel(model, options)` | 请求切换模型及请求选项；由 Agent 在规定边界应用 |
| `Cancel()` | 取消当前 Run，并清空此操作发生时尚未消费的纠正与后续输入 |
| `Snapshot()` | 读取当前状态、历史和排队概况，只读 |
| `Close()` | 停止接受新任务，取消运行和待执行任务，并等待工作流程退出 |
| `RunHandle.Wait(ctx)` | 等待该 Run 的最终结果；等待超时不取消任务 |
| `RunHandle.Cancel()` | 取消该句柄对应的任务；若仍在队列中，只移除该任务 |

活动任务的句柄取消等价于取消当前 Run，并清理当时的旧输入队列；避免两种活动任务取消行为不一致。

`Submit` 的 context 管理该次任务的生命周期，取消后不再启动该任务或继续其执行。UI 应使用会话级生命周期派生 context，而非短暂的页面刷新或 HTTP 请求 context。

### 配置与依赖

Agent 配置包含：

- `llm.Model`、`llm.RequestOptions`、系统提示。
- 与现有 Provider 兼容的 `StreamFunc`。
- 工具列表。
- 串行调用的事件接收函数。
- `MaxSteps` 和 `MaxParallelTools`。

默认值：

- 每个 Run 最多 20 次模型调用，切换模型也计入。
- 工具最大并发数为 4。
- 配置值为零时使用默认值，负数拒绝。
- 本轮不扩展 TOML；装配层使用默认值或显式传参。

Agent 依赖 `llm`，不读取配置文件，不依赖具体 Provider、demo、UI 或会话存储实现。工具由装配层注册，不在核心写死工具名称。Session 与 Agent 的装配、历史加载和保存由外层协调，本轮不为尚未实现的存储系统增加空接口。

### 状态和结果

区分两种结果：

- `AssistantMessage.State`：一次模型调用的结果，继续使用现有定义。
- `RunResult`：整次任务的结果，可以是完成、失败、取消、达到调用上限或输出截断。

保留 RunID、模型调用次数、产生的消息、按模型归类的用量、失败原因和必要的底层 error。

`Wait(ctx)` 返回的等待 error 与 `RunResult` 中的任务失败明确区分。最终结果独立存储，不能依赖 UI 收到结束通知，也不能依赖事件被消费。

模型、请求选项、工具定义及已发布消息按只读契约使用。仅在需要修改切片或内容块时作局部复制，不建立通用深拷贝体系。

## 三、循环、工具、纠正、取消和模型切换

### 正常循环

1. 开始一个 Run，将用户消息加入历史。
2. 应用待生效的模型选择，消费纠正，准备本次请求。
3. 调用 Provider，转发其流式事件。
4. 从 `Result()` 取得最终消息，保存该次调用结果。
5. 根据状态与结束原因决定是否执行工具。
6. 工具完成后追加配对结果，再进行下一 Step。
7. 模型正常回答且不再调用工具时结束 Run。
8. 正常结束后，按 FIFO 启动下一项用户提交。

没有任务时后台工作流程等待，不忙轮询。不会为每个 token 或每个通知创建 goroutine。

模型失败、用户取消、内部错误、调用上限和输出截断均停止当前 Run；失败时不自动推进旧的排队任务，队列中的任务结束为“未执行”，防止后续任务依赖一个没有完成的前置任务。

### 工具契约与调度

提供可执行工具结构，复用 `llm.Tool` 保存名称、描述和 Schema，另增加：

- `ParallelSafe`：是否允许与相邻的同类声明工具并行，默认 false。
- `Execute`：接收 context、调用 ID、已解析参数和可选进度回调，返回工具内容及 error。

工具返回内容继续使用 `llm.ContentBlock`。Agent 负责生成带匹配 ID 的 `ToolResultMessage`，工具不自行修改会话历史。

参数由具体工具检查，不引入完整 JSON Schema 验证框架。注册时检查缺少执行函数、空名称和重复名称；响应中调用 ID 缺失或重复时，不执行无法正确配对的工具。

调度规则：

- 连续且声明 `ParallelSafe=true` 的调用组成并行组，受并发上限约束。
- 串行工具必须等前组结束；自身结束后才启动后组。
- 结果按模型原始调用顺序加入历史，执行结束通知可以按实际完成顺序到达。
- 不按名称推断工具是否安全，不做资源冲突图。
- 进度回调只报告观察值，不把每次进度当成最终工具结果。
- 工具返回后继续报告进度属于工具契约错误，不支持后台偷偷续写结果。

普通参数错误、未知工具、工具执行错误转成 `IsError=true` 的结果，让模型自行纠正；其他独立工具继续处理。context 取消停止调度。工具 panic 作为内部执行故障报告，不悄悄当成普通成功结果。

只有完整、成功且以工具调用结束的模型响应才能执行工具。错误、取消或长度截断的响应不执行其中的调用。

### 纠正与排队

`Steer` 与 `Submit` 的含义由调用入口决定，Agent 不识别“继续”“停止修改”等自然语言关键词。

- `Steer` 进入当前 Run。
- 忙碌时的 `Submit` 排队，等待成为新的 Run。
- 多条待消费纠正按到达顺序加入下一次请求。
- 纠正不强行中断已经开始的模型请求或工具。
- 在模型响应完成、工具执行组结束及启动下一项工具前检查纠正。
- 有纠正时，不再启动剩余旧工具；为其生成“因用户纠正而未执行”的错误结果，然后将纠正交给模型。
- 正常结束前再次检查纠正，确保已经接受的输入不被遗漏。

### 取消

取消操作在同一临界区内标记当前 Run 正在停止，取走并取消当前模型/工具 context，清空当时尚未消费的输入。

- 取消不回滚文件、进程或其他已经产生的副作用。
- 已完成工具保留真实结果。
- 未启动工具标记为未执行。
- 被取消工具如无法确认外部操作结果，应明确表示“执行已中断，副作用可能已发生”，不能声称未执行。
- 等已启动工具响应取消并退出后，才释放当前运行的执行权。
- 不通过遗弃 goroutine 假装取消成功；工具实现必须遵守 context。

取消后到达的新提交保留，等旧 Run 收尾再启动。被清空的排队任务，其句柄必须取得取消结果，不能永久等待。

下一次用户输入“继续”按普通请求处理，由模型结合历史判断；不自动重放之前的工具。

### 跨模型、跨协议切换

`SetModel` 记录下一目标，Model 与 RequestOptions 成组替换：

- 空闲时直接生效。
- 旧模型正在生成时，取消该次模型请求，保留已观察内容，不执行该响应中的工具。
- 工具执行期间不取消已启动工具；停止启动其余调用，等待在途工具结束。
- 为未执行的调用补齐明确的工具错误结果。
- 整理上下文后，由新模型继续当前 Run。
- 等待期间重复切换取最后一次目标；相同目标且选项未变视为无操作。
- 不修改当前在途请求的模型、凭据或协议。
- 取消、Close、Run 的 context 结束优先于模型切换，不能因切换自动复活任务。
- 切换导致的单次模型请求取消不等于整个 Run 被用户取消。
- 每次已发起模型调用计入上限，防止切换绕过限制。

分别发布“切换请求已接受”和“新配置已生效”通知。排队任务在实际启动时采用当时生效的模型。

## 四、历史、事件和扩展边界

### 原始历史与模型输入

本节的原始历史指 Agent 当前持有的内存记录，不代表已经写入 Session 存储。Agent 在执行中追加历史事实，不在切换时原地改写旧消息。请求准备逻辑独立放在 Agent 包内；后续 Session 层保存原始记录，面向具体模型的请求投影仍由 Agent 准备，不提前建设记忆系统。

初版规则：

- 完整成功消息和配对工具结果正常参与上下文。
- 失败或取消的 assistant 响应保留供观察，但不直接作为可执行的 assistant 历史回传，避免传入半截工具调用或签名。
- 已执行工具所属的完整 assistant 消息保留，工具结果包括真实结果和明确的未执行说明。
- 同一模型来源的完整思考块正常回传。
- 不同 Provider、API、模型 ID 或服务地址的思考块从目标请求中移除；签名、redacted 数据不转换、不伪造。
- 移除思考后为空的 assistant 消息不进入请求。
- 工具 ID 和配对关系保留，不任意重命名。
- 切换后如最后一条消息是 assistant 正文，需要继续生成，则在本次请求中追加明确标为运行控制说明的 user 消息，要求接续当前任务；该说明记录为程序生成，不冒充用户原话。
- 不自动丢弃图片等业务内容；目标适配器不支持时明确失败。
- 输出截断停止 Run，不自动续写；其中未执行工具明确标记。下一次请求不回传不完整的工具结构。

实际历史投影必须通过取消后继续、工具中途切换和跨协议切换验收，不能只验证普通文本转换。

### 事件与观察

保留现有 LLM 事件，不再增加同义的文本、思考 Delta 类型。Agent 事件只增加必要层次：

- Run 开始、结束。
- Step 开始、结束。
- LLM 事件包装。
- 工具开始、进度、结束或未执行。
- 输入接受、丢弃及模型切换通知。

事件携带 RunID、Step 编号，工具事件另带调用 ID。事件回调串行执行，不持有 Agent 状态锁调用外部函数，避免回调查询状态或提交控制操作时死锁。

回调必须快速返回；它用于交接事件，不能直接承担慢速 UI 渲染或等待用户输入。未来 UI 通过自己的状态及通知层合并刷新，不丢弃核心工具结果。

模型消息终态与 Run 终态分别保留含义。Run 最终结果先写入并解除等待，再发布结束通知；消费者缺席不能阻止结果取得。

### 后续扩展

| 能力 | 接入位置 | 明确不属于核心的部分 |
|---|---|---|
| Session 管理与持久化 | 装配层加载会话历史交给 Agent，并将已提交的历史及 Run 结果交给独立的 `session` 包保存 | 会话 ID、标题、列表、分支、数据库、文件格式与恢复索引 |
| 上下文压缩 | 请求准备前 | 摘要算法、token 估算策略 |
| 记忆 | 请求准备时提供材料；结束后读取事实 | 检索、长期存储、经验提取、自进化策略 |
| SubAgent | 外层运行管理创建独立 Agent | 委派策略、父子预算、共享资源协调 |
| Sandbox | 具体工具的执行环境 | 进程、网络及文件系统隔离实现 |
| 权限审批 | 工具执行前的外层包装 | UI 审批、权限规则存储 |
| UI / RPC | 提交、控制、状态和事件接口 | 渲染、网络重连、远端订阅 |

不只为 sandbox 预留 shell 替换：后续 read/write/edit 等也必须通过受控执行环境，才能形成完整隔离。

SubAgent 默认不共享可变历史；它返回的结果由父任务显式接收。父子任务取消和资源权限留到对应阶段落实，不在本轮复制多 Agent 框架。

## 五、分阶段实现与验收

按顺序交给实现模型，每次只完成一项；每项说明实际改动、接口变化和未完成内容。

### 任务一：执行核心与单工具

建立核心类型、同步循环、内存历史记录及串行工具执行。复用加法工具，先验证无工具回答、单工具往返和工具错误纠正，不接入队列与模型切换，不创建 Session 管理或存储包。

### 任务二：后台运行与观察接口

实现 Agent、Submit、RunHandle、结果等待、Snapshot、事件顺序及关闭。demo 改为调用 Agent，旧的纯 LLM 实验继续保留；不维护第二套正式工具循环。

### 任务三：并行、纠正、排队和取消

实现受限并行、串行边界、纠正检查点、FIFO 后续任务和取消清队列。用可等待、可报告开始结束的演示工具验证，不用真实文件修改制造并发实验。

### 任务四：模型切换与历史投影

支持空闲、生成中、工具执行中切换。依次验证同协议跨模型、跨协议、连续选择目标，以及切换与取消并发发生。

### 任务五：真实联调与文档

使用现有配置中的可用模型，在控制台完成：

- 普通回答、单工具、多工具及工具错误后纠正。
- 有并行工具时串行工具不会提前执行。
- 纠正后未启动的旧工具不执行。
- 取消只清理当时的旧输入；之后新提交正常工作。
- 等待结果超时不取消运行。
- 不接收展示事件也能取得最终结果。
- 模型生成中切换不会执行旧响应的工具。
- 工具运行中切换只等待已启动工具，下一次请求使用新模型。
- 跨协议工具历史保持配对，原始历史不被修改。
- 达到调用上限明确结束，不执行新一轮动作。
- 多次读取句柄结果一致，所有被取消的排队句柄都能结束等待。
- Close 后没有仍在运行的本阶段自建工作流程。

本轮不新增自动化测试文件；每阶段执行 gofmt、`go build ./...`，并记录对应手动验证结果。并发行为需要受控的本地演示场景，不能只依赖模型恰好生成某种输出。

无法验证的真实签名或服务兼容行为如实保留“尚未验证”。不修改模型参数绕过失败，不自动重试，不宣称覆盖全部协议语义。

文档保留设计决策、阶段进度和验收记录。除非另行要求，不提交或推送 Git；后续上传遵守按包分支、文档使用 doc 分支的既定约定。
