跨会话共享通过目录实现：不同会话的调用方打开同一目录即可共享主题。用户/项目目录划分属于外部，本包不认识用户 ID、项目 ID 或 SessionID。

## 4. 包结构与接口

包名固定为 `longterm`，导入路径 `CodeAgent/internal/memory/longterm`。

```text
longterm/
    types.go          # 公开类型、限制、错误
    service.go        # Open、Close、同目录串行访问
    recall.go         # 读取、检索、直接管理、游标读取
    document.go       # Markdown 格式与索引
    tools.go          # 私有工具 schema 与执行校验
    consolidate.go    # 有界模型循环与来源转录
    store.go          # 目录内读写和状态
    transaction.go    # 提交日志及恢复，体量小时可并入 store.go
    README.md         # 示例、边界、恢复契约、限制
```

不再建立 config/service/store/repository 子包，不用一函数一文件。优先保留现有公开接口形状：

```go
Open(directory string, options Options) (*Service, error)
(*Service).Close() error
(*Service).ReadIndex(ctx context.Context) (Document, error)
(*Service).Read(ctx context.Context, path string) (Document, error)
(*Service).Search(ctx context.Context, query string, limit int) ([]Match, error)
(*Service).Put(ctx context.Context, entry Entry) error
(*Service).Forget(ctx context.Context, path string) error
(*Service).Consolidate(ctx context.Context, batch Batch) (Outcome, error)
(*Service).Cursor(ctx context.Context) (string, error)
```

固定契约：

- Options 保留显式 Model、RequestOptions、Stream、Limits。Stream 使用当前 llm.Request/StreamReader。
- Source 包含稳定 ID 和 llm.Message，不导入 compact.Source，不改写或重新排序输入。
- Batch 保留 ID、Cursor、Sources。ID 在目录内唯一，来源至少一条，来源 ID 非空且批内唯一；拒绝 nil/typed-nil 消息。
- Cursor 是调用方提供的不透明标记，本包不解析、比较或据此查历史。Cursor() 返回目录内最后成功批次的标记，不是各会话的最后消息 ID。多会话选择和进度聚合由后续上层负责，本阶段不新增调度机制。
- Outcome 保留 Changed、Duplicate、Cursor、Turns、ToolCalls，增加 Usage。Changed 表示主题/索引改变，单独更新批次状态不算内容改变。
- 同 ID、同有效输入及 Cursor：Duplicate=true，不再调用模型。同 ID、不同有效输入或 Cursor：ErrBatchConflict，不改变记忆。
- Duplicate 返回原批次回执的 Cursor，不能返回其他新批次的标记；状态中保存所需最小回执。
- 无 Stream 仍能 Open/Read/Search/Put/Forget。只有需要新整理时返回 ErrNoModel；已成功批次的去重不依赖模型可用性。

## 5. 适配当前 LLM，禁止恢复废弃接口

先读 internal/llm 的 request.go、message.go、content.go、stream.go、state.go、usage.go。

- 当前没有 llm.RequestContext、llm.CloneMessage、llm.CloneContent、llm.CloneArguments、ToolResultMessage.ModelContent。不得继续引用，也不得修改 llm 补回。
- 遵守共享只读契约：调用期间输入消息、嵌套 map/slice、选项以及回调收到的请求均只读。调整输出上限时值复制 RequestOptions。不另建通用深拷贝框架。
- 自行构造新的请求列表和工具目录，不原地修改输入或流快照。只读不是 Go 冻结，不支持调用方同时修改。
- 来源先转为私有精简转录结构再序列化。不要直接 Marshal 整个 llm.Request、内部完整消息或 RequestOptions。
- 只传来源 ID、角色、可见文本、工具调用名称/ID/参数、结果和 IsError 等必要证据。不传 Details、鉴权、签名、Thinking、RedactedData、图片 base64。
- 图片使用“包含图片，本次未进行视觉提炼”占位。可提炼同条消息的文字，不推断图片内容。
- 历史工具调用仅作为转录数据，不能执行。只执行整理模型本轮产生的白名单调用。
- 输入来源、旧记忆、工具结果都是数据，不能修改权限。助手计划不是执行证明，失败工具结果不能写成成功事实。
- 以有序精简来源转录和 Cursor 计算稳定批次摘要；不含鉴权、无关内部字段或会变化的旧记忆。同样来源重试应稳定。

## 6. 记忆内容与格式

一份文件保存一个相关主题。沿用 Markdown frontmatter：description、type、sources。类型只允许 user、feedback、project、reference。

保存跨会话有用的偏好、纠正与原因、项目约束与适用范围、参考信息。不写逐轮摘要、临时日志、待执行计划、凭据、推测、重复项目指令或源码/Git 可直接推导的普通事实。

README 和离线行为验证必须包含此例：

1. 第一批：“项目不用 ORM，因为我要直接控制 SQL。”保存约束与原因。
2. 第二批：“后台管理模块允许 ORM，核心链路还是不用。”读取旧主题，更新范围。
3. 最终是一份包含例外与原因的主题，索引同步更新，不能变成两条未解释的冲突规则。

假模型测试验证读取/更新机制，不证明真实模型语义准确率。

来源规则：新主题 sources 来自本批真实 Source.ID。更新已有主题时，代码将已读旧主题的来源与本批修改依据合并去重，避免丢失仍保留事实的出处。模型只声明本批 source_ids，不能虚构旧来源。文件级来源只是主题来源集合，不是逐句真实性证明。删除操作的来源依据可保留在事务元数据中，不另造审计服务。

MEMORY.md 由代码按主题摘要稳定排序生成，模型和 Put 不得直接写。摘要单行、最多 200 个 Unicode 字符；索引截断不输出半条链接。Search 保持支持中文的大小写归一字面匹配，返回路径、行号、片段，不宣称语义检索。

## 7. Consolidate 的固定流程

1. 校验 context、Batch、来源，准备精简转录与稳定摘要，检查大小。
2. 获取同目录锁，恢复未完成提交，读取状态，检查去重和冲突。
3. 新批次检查 Stream，读取索引和清单。初始请求含整理系统提示、索引、清单和本批来源，不无条件塞入全部正文。
4. 创建暂存区，模型仅使用 memory_list/read/search/write/edit/delete 六个工具。
5. 后续 read/search/list 必须看到暂存的新建、修改、删除以及对应的暂存索引。
6. 合法成功终态且无工具调用时，校验最终主题、索引、批次状态，统一提交。允许无改动，仍登记成功批次与 Cursor。
7. 返回回合数、工具次数、用量与结果。失败不能返回貌似已保存的 Changed/Cursor；提交待恢复按第 9 节区分。

工具约束：

- schema 与运行时校验一致，拒绝未知工具/参数、缺失参数、错误类型、无效或重复来源。
- 修改/删除磁盘已有主题前必须实际 memory_read；list/search 不算读。新建无需先读不存在文件；随后 edit/delete 须先读暂存主题。
- memory_edit 仅在正文做一次精确替换，拒绝空 old_text、多处匹配、无匹配，不能静默退化为覆盖。
- call ID 非空且本次循环不重复；同轮多调用按返回顺序执行，结果 ID 对应。
- 参数或执行校验失败，本批失败并丢弃暂存，不添加无限模型修复/重试。
- 工具仅访问本目录，不导入通用 tools、agent、MCP，不开放 Bash、网络或其他目录。

## 8. 预算、终态和取消

沿用现有默认值：Turns=5、ToolCalls=24、InputBytes=256000、OutputBytes=256000、FileBytes=64000、Files=256、IndexLines=200、IndexRunes=25000。零值用默认，负值拒绝；这些是资源预算，不是精确 token 估算。

- RequestOptions.MaxTokens=0 默认 4096，若 Model.MaxTokens 为正则不能超出；负值拒绝。模型显式提供，不静默回退。
- 每次调用前检查提交的系统提示、消息、工具定义序列化大小，排除传输鉴权。超限明确失败，不截掉来源后声称已处理，不新增分块或重试。
- 检查总回合、工具次数、输出、最终文件和索引预算。状态和事务日志也在提交前检查，不能写完正文才发现超限。
- delta 与快照不重复累计同一输出；分别作增长检查，最终消息和工具结果按明确口径计入总预算。
- 检查建流错误、nil reader、InternalErr、State、StopReason、内容类型和调用一致性。StateSuccess + StopToolUse + 有调用才可继续工具循环；StateSuccess + StopStop + 无调用才可提交。
- StopLength、模型错误、未知终态、不匹配的工具终态、耗尽预算都失败，不接受截断为完成。正常终止可以没有文本，表示无额外内容。
- Stream 必须响应 context，Close 必须解除 Result 阻塞；取消时不进入不可中断的 Result 等待，不为此修改 llm。若使用辅助 goroutine，保证按此契约退出。
- 模型/工具阶段失败或取消，不写主题、索引、成功批次或 Cursor。可返回已发生 Usage，不代表成功提交。
- 不把完整请求、密钥、原会话写成调试日志。任意来源文本中的秘密不能靠通用规则保证全部识别，不宣称绝对脱敏。

## 9. 存储、提交和恢复

Markdown 仍是实际记忆格式，不新增数据库。保留 os.Root 受限访问、普通文件检查、UTF-8 校验、单文件临时写入/Sync/Rename、同目录进程内共享锁。

路径检查覆盖穿越、绝对路径、斜杠、Windows ADS、设备名、索引保留名及内部状态/日志。现有注释声称拒绝设备名，必须实际检查 CON、PRN、AUX、NUL、COM1 等，不能只信注释。不得沿符号链接读写目录外文件。

### 9.1 固定采用可重放提交日志

采用一个有界目录内 pending 日志，不建立通用事务框架。日志包含版本、目标主题最终内容/删除集合、最终索引、最终批次状态及必要回执，不含传输配置或完整来源转录。批次状态上限沿用 8 MiB，pending 日志上限定为 32 MiB，写入与恢复读取均检查序列化后的实际字节数；即使自定义文件预算更大，超出日志上限也必须在发布前拒绝。

顺序固定：

1. 锁内算出并校验全部目标内容、状态、日志，检查取消。
2. 原子写入 pending 日志；日志成功发布是不可撤销的恢复点。
3. 按固定顺序写主题、更新索引、删除旧主题、写批次状态。删除不存在文件视为幂等成功。
4. 完成后移除日志，再返回成功。

### 9.2 必须准确区分失败阶段

- 日志发布前失败/取消：主题、索引、成功状态不变，可重新整理。
- 发布后取消：不按普通取消中断本地提交，尽量完成；I/O 失败则保留日志。
- 发布后 I/O 失败/进程崩溃：磁盘可能部分改变，返回可判断的“提交待恢复”错误，不能说完全未写入或已回滚。
- Open 和现有 Service 的每次后续数据操作（Close 除外），在同目录锁内先恢复 pending；恢复成功前不能读部分结果、启动新模型整理或覆盖事务。
- 恢复只重放目标状态，不调用模型；恢复后的相同批次命中去重。
- 恢复时仍验证日志版本、路径、大小和内容结构。损坏日志明确失败并保留，不忽略/删除后继续。
- Put、Forget 使用同一机制，没有 Batch 也不能留下索引不一致。
- 包内读取借助锁避开部分提交，外部直接读文件不受保护，不能声称跨文件瞬时原子可见。
- 只承诺已发布日志可用于 I/O 失败/进程中断恢复，不夸大为所有平台、突然断电和磁盘损坏均有事务保证。

跨进程写入和外部编辑由调用方协调，不新增分布式锁。Close 不与操作并发；同目录一实例 Close 不能破坏另一实例的串行保护。第一版 Consolidate 从读取旧记忆到提交期间一直持有目录锁；模型回调不得重入同目录 Service，避免死锁。允许其他读操作等待，暂不引入乐观版本检查或无锁快照。

旧主题应仍可读。扩展状态版本和回执时兼容 `.memory-state.json`：保留旧批次标记；无法安全比较旧摘要算法时，明确返回旧格式冲突/需迁移错误，不能当作新批再次调用模型。不静默清空记忆/状态，不擅自淘汰批次记录来腾预算。

## 11. 离线验收

使用临时目录、固定消息、假 Stream、可控 reader、局部 I/O 故障注入。不调用真实模型、不读用户记忆、不联网；不为测试公开通用文件系统接口或新增依赖。行为测试可用仓库外临时文件及 Go overlay，必须记录实际命令，不能用 `[no test files]` 冒充验证。

必测清单：

1. 独立性：不依赖 memory 父包/compact/agent/runtime/session/provider/tools，父目录没有多余旧实现。
2. 无模型：空目录、Put/Read/Search/Forget、重开持久化、同目录两实例、无模型新整理失败。
3. 格式与边界：中文/非 BMP/CRLF、200 字摘要、索引截断、文件/索引预算、非法路径/设备名/索引写入/符号链接；拒绝操作不越界。
4. 整理功能：新建、读后更新、合并、删除、无变化、不同批次更新同主题；暂存读取/清单/搜索/索引一致；ORM 例外示例。
5. 工具限制：未读修改、伪造来源、错误参数、重复 call ID、未知工具、同轮多调用、edit 多处匹配；历史来源调用不执行。
